The studio

Hollovar Labs is an independent software studio. It publishes small Android applications that solve a specific, ordinary problem and then get out of the way — no accounts, no advertising, no analytics, and as few permissions as the job can be done with.

The name comes from the Hungarian Hollóvár, raven castle. The accents come off for international use; the raven stays, for the reasons ravens are usually invoked — attention, and a long memory.

The software is written by one developer: a physicist with a doctorate and a career spent on scientific and industrial software — measurement systems, instrumentation, hardware and software that have to agree with each other, and desktop and mobile applications in C#, .NET and Android. That background is the whole explanation for how these applications are built. An instrument that quietly makes up its readings is worthless, and so is an application that quietly makes up what it does with your data.

Privacy is a build decision, not a policy page

Most applications ask you to trust a paragraph. The more useful thing is to remove the capability, so the paragraph has nothing to promise.

TiltFlow asks you for exactly one thing: permission to run its accessibility service, which you switch on yourself in Android's settings. Android allows no other route for an application to swipe on your behalf, and swiping is the entire product. You can switch it off in the same place at any time.

What it never asks for is everything else. The released build declares no Android permissions — not even internet permission — so it has no route by which to send anything anywhere. And the service is declared canRetrieveWindowContent="false", so Android will not hand it the contents of your screen at all. It is unable to read your screen, rather than promising not to. Both are in the application's manifest, where anyone can check them.
